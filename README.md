# 疯狂水世界 AutoJs6 辅助工具

基于 [AutoJs6](https://github.com/SuperMonster003/AutoJs6) 的 Android 自动化脚本，用于“疯狂水世界”。脚本通过截图模板识别游戏状态，再由悬浮控制面板按配置调度任务。

> 仅供学习交流使用。自动化会产生游戏内操作；请自行确认游戏规则、账号风险和当前页面状态。

## 当前功能

| 任务 | 能力与关键边界 |
| --- | --- |
| 种植 | 收割、翻地、播种；库存满时切换作物。未确认选种界面、出现建筑蓝图或处于冷却期时不猜测点击。 |
| 锻造 | 按配置检查并执行锻造；可限定为仅周五执行。 |
| 打捞资源 | 钓鱼固定第 1 行、拾荒固定第 2–4 行、深潜固定第 5–7 行。类别模板重叠或入口未确认时安全退出。 |
| 贸易港口 | 处理可见的收货、交货和任务返回。 |
| 居民需求 | 依据经验阈值判断满足或刷新；可选周四按金币阈值判断。物资不足、OCR 结果不确定或处于“立即完成”协商状态时不执行高风险点击。 |
| 展区 | 领取动态展品气泡，配置寻宝时长和地点，并在已确认的组队页处理派遣。 |
| 情报 | 进入情报页、处理可执行事件和奖励；没有空闲舰队或关键页面未确认时退出本轮。 |
| 资源收集 | 分别控制挂机奖励、主城经验气泡和工厂生产物资；无目标是正常轮询结果，保持静默。 |
| 搁浅商船 | 整点前进入活动弹窗，整点打开货轮列表并出征；无空闲舰队时按配置等待下一轮重试。 |
| 盟战 | 在 20:00–21:00 按三支舰队计划执行集结、进攻或防守，可分别配置优先城镇和加速开关。钻石加速必须确认标题、倒计时和对应行状态。 |

所有任务均从悬浮面板启用，默认不会因脚本升级而自动打开。总调度会在任务之间确认场景；无法确认当前页时，使用已识别的返回模板进行有限恢复，恢复失败则保留失败证据并等待下一轮。

## 运行环境

- Android 设备或 MuMu 模拟器
- [AutoJs6](https://github.com/SuperMonster003/AutoJs6) App
- 屏幕分辨率：1080 × 2400（仅支持此分辨率）
- Android API 版本 >= 24
- AutoJs6 的应用列表、无障碍、后台弹窗、悬浮窗和录屏权限

模板坐标和相似度以当前游戏画面为准。更换分辨率、游戏版本或 UI 主题后，应先重新采集模板并完成对应任务的实机验证。

## 运行方式

1. 将项目放到设备 `/sdcard/脚本/水世界/`
2. 在 AutoJs6 中打开 `main.js` 并运行
3. 在主页依次开启所需权限；点击启动后，脚本会启动游戏并申请录屏权限
4. 点击悬浮球打开控制面板，配置并启用需要的任务，再启动总调度

停止总调度或关闭悬浮面板后，重新运行脚本才会加载新同步的模块。仅完成文件同步或哈希校验，不代表运行中的 AutoJs6 实例已经加载新代码。

## 运行日志与 AI 分析

每次脚本运行都会将业务日志追加到设备的 `/sdcard/水世界运行日志/`，使用 JSONL 格式记录时间、级别、消息、异常堆栈及可用时的错误截图路径。单个日志分段最大 2 MiB，设备仅保留最近 8 次会话；日志不在脚本同步目录内，因此定向同步代码不会覆盖诊断证据。

在 Windows 上运行以下命令可拉取 MuMu 最新会话的全部日志分段和错误截图，并生成最后 300 行的 AI 分析摘要：

```powershell
pwsh -NoProfile -File .\tools\pull-mumu-runtime-log.ps1
```

有多个 MuMu 实例时，显式指定设备序列号：

```powershell
pwsh -NoProfile -File .\tools\pull-mumu-runtime-log.ps1 -Serial emulator-5556
```

诊断工具会将 TCP serial 中 Windows 不允许的字符替换为下划线，仅影响本地导出目录名，原始 serial 仍保留在日志元数据中。

`tools/full-flow-config-probe.js`、`prepare-full-flow-config.js` 和 `restore-full-flow-config.js` 用于一次完整调度验收前备份配置、临时缩短冷却和完成后恢复用户偏好。它们只应在明确计划的验收中运行；准备脚本会改写设备侧配置，但不会直接触控游戏。

## 悬浮面板配置

控制面板提供任务总开关、执行间隔和任务详情页：

- 居民需求：巡检间隔、经验阈值、周四金币模式及金币阈值；“今日已完成”按设备本地日期显示。
- 展区：完成后的间隔、寻宝时长和地点。
- 资源收集：挂机奖励、收集资源、工厂生产收集三项开关及各自间隔。
- 商船：提前进入活动弹窗和重试间隔。
- 盟战：每支舰队的模式、优先城镇、维修/行军加速；同一倒计时阶段最多加速一次。

运行期间配置控件会锁定，避免任务正在执行时修改其页面状态和调度契约。

## 项目结构

```
main.js                  # 主页、权限检查、启动/停止和调度入口
modules/
  floatingPanel.js       # 悬浮球、任务配置与本地持久化
  scheduler.js           # 任务时序、冷却、场景恢复和互斥规则
  gameHelper.js          # 模板加载、识图、OCR、截图与公共安全提示
  navigate.js            # 场景识别和有限返回主界面流程
  plantFood.js           # 种植
  weapon.js              # 锻造
  resourceGather.js      # 钓鱼、拾荒、深潜
  tradePort.js           # 贸易港口
  residentDemand.js      # 居民需求
  exhibition.js          # 展区寻宝与气泡领取
  intelligence.js        # 情报任务
  hangUpReward.js        # 挂机奖励
  resourceCollection.js  # 主城经验和工厂物资收集
  merchantShip.js        # 搁浅商船
  fleet.js / war.js      # 舰队和盟战
img/                     # 运行时模板；同一任务的模板与脚本应一起更新
test/                    # Node 桩回归测试
tools/                   # 日志拉取与完整流程验收工具
```

## 验证边界

`test/` 中的 Node 测试覆盖调度顺序、模板缺失保护、状态流转和配置契约，但不会驱动 MuMu 或真实游戏。通过测试、静态检查、文件同步或 SHA-256 一致，均不能替代一次新的实机页面和目标动作验收。

在修改模板、坐标、游戏页面流程或涉及钻石/英雄选择的逻辑后，应先查看最新 JSONL 日志和截图；只有在页面、目标和风险状态都被确认后再进行实机验证。
